## 解释边界核对

- 原始失败仅记录 HTTPError 类，不能追溯区分 401、429 或其他 HTTP 状态。正文把后来重放诊断与原始失败明确区分，未将全部历史错误归因为余额不足。
- 失败均保留在预定 target 分母，避免事后删除失败样本。由此得到的是 pipeline 分数；不平衡 HTTP 故障与运行顺序使这些分数不能识别模型能力或方法因果效应。正文、表题、图题与限制均有说明。
- 零次程序执行意味着 program-enabled 条件未形成所需的执行对照。正文明确写为 failed manipulation，并禁止正反两方向的程序自演化结论，符合证据。
- 笔记实际被读取只证明处理确实发生，不保证改善来自规范归纳。正文没有越过这条界限。
- Manifesto 无实证、moderation 未完成复现、无专家确认缺口、无样本充足阈值等欠缺均已披露。

本轮没有新增必须修改的 blocker。正式论文若要进一步声称学习曲线、模型差异或程序演化效应，仍须在稳定服务、实际处理差异和更充分评测下重跑；当前受故障影响的样本不提供这些结论。
